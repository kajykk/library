## 2. 决策 2：模型二选一（仅当选 B 或 C 后续继续）

任务书原候选 `multilingual-e5-small` 在 fastembed 0.9.1 中**不存在**（e5 只有 large，2.24 GB 权重，直接超线），所以只能在下表二选一。

| | `BAAI/bge-small-zh-v1.5` | `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` |
|---|---|---|
| 权重 | 90.8 MB（MIT） | 240.5 MB（Apache-2.0） |
| 维度 / token 上限 | 512 / 512 | 384 / **128** |
| 15 条查询 semantic 命中 | 12/15（q05、q06、q14 落空） | **14/15**（仅 q07 落空） |
| 平均 top-5 精度 | 0.39 | 0.41 |
| 索引吞吐（threads=4, batch=8） | 17.6 chunk/s → 全库 2 h 15 min（threads=8 网格最优 17.4，无提升） | 31.0 chunk/s → 全库 1 h 24 min |
| 常驻内存外推 | ≈661 MB | ≈824 MB（上界，受前一轮 ORT arena 影响） |
| 截断实况 | 68.3% 的 800 字切片超 512 token，尾部静默丢弃 | **每条切片都被截到 128 token**，约 84% 字符未进入模型 |
| 若继续必须一起改的东西 | 无（切片参数可保持 800/120） | 切片必须缩到 ≈200 字（否则丢内容），索引 chunk 数随之上升，索引耗时还要再乘 ~4 |

- 第三个选项：**再跑一轮 spike** 换候选（fastembed 注册表里还有 `minishlab/potion-multilingual-128M`、`intfloat/multilingual-e5-large`、`BAAI/bge-base-en-v1.5` 等），需再次联网下载并另计体积。
- 执行方观察但不代为决定：multi 的分数优势建立在「只用切片开头 128 token」之上，若按它自己的 token 上限重切，成本模型要整体重算；bge 与 800 字切片更契合，但吞吐只有 multi 的 57%。

## 3. 决策 3：依赖授权 G2（是否允许新增嵌入依赖）

| 项 | 需要用户确认的具体内容 |

| 3-2 落点 | 只写 `server/requirements-semantic.txt`，**不进** `requirements.txt`、**不进** `requirements-dev.txt`、**不进** CI、**不进** Docker 镜像；运行时由 feature flag 控制导入 |
| 3-3 ANN | 本轮实测暴力点积全库外推 53–70 ms（bge），**不建议引入 hnswlib**；若用户仍要，需单独批准其安装体积 |
| 3-4 权重来源 | 模型权重缓存位置（生产建议 `server/data/semantic-models/`，属 `server/data/`，写入需 G1 单独授权）、锁定 HF revision hash、离线运行（`HF_HUB_OFFLINE=1`） |
| 3-5 体积余量 | wheel 只余 39 MB 余量；若将来要 `sentence-transformers`/torch 方案，必须重新走一次 G2，本批准不覆盖 |

| **A. 不做**（任务书默认） | 只做到 B5-10「证据式回答」：返回段落与出处，不生成自然语言 | 无 |
