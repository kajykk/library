## 概要

| 指标 | 数值 |

| 重复 sha256 组 | 52 |

保留策略 `best`：有封面 > 有正文 > 有意义标题 > 创建时间最早 > id 稳定排序。仅处理 `deleted_at IS NULL` 的存活文档，每组保留 1 本，其余写 `deleted_at`；不硬删除、不删除文件。

## 重要发现：3 组“假重复”

以下 3 组的文件内容相同，但实际是错误页或空文件，**不应按重复去重**：

| sha256 前缀 | 文档数 | 文件大小 | 判定 | 说明 |
|---|---:|---:|---|---|
| `16ee58a7` | 6 | 143 B | tiny_error_page | 4 个 EPUB + 2 个 `<title>410 Gone` 的 MOBI（其中标题本身即 410 页面） |
| `74a32f41` | 6 | 143 B | tiny_error_page | 6 个 EPUB，均为 z-library 下载返回的 410 错误页 |
| `e3b0c442` | 3 | 0 B | empty_file | 空文件（sha256 为空内容常量） |

这些记录的标题看起来是真实书目，但文件只有 143 B 或 0 B。若按普通重复组处理，会把同组 5 / 5 / 2 本全部软删，只剩 1 本同样无效的文件。脚本因此默认跳过，并可通过 `--include-suspicious` 强制纳入（需人工确认）。

`--include-suspicious` 时计划变为 49 组 / 62 本，其中包含上述 12 本无效文件。

## 脚本行为

```bash
# 预览（默认 dry-run，只读）
python server/scripts/dedup_sha256.py

# JSON 输出
python server/scripts/dedup_sha256.py --json

# 指定保留策略
python server/scripts/dedup_sha256.py --strategy oldest   # best(默认)/oldest/newest

# 执行软删除（需单独授权；先停止 uvicorn）
python server/scripts/dedup_sha256.py --apply
```

`--apply` 流程：

1. 完整备份 `knowledge_base.db` 及 `-wal` / `-shm`；
2. 只对 dry-run 计划内的安全组执行；
3. 按 `WHERE id = ? AND deleted_at IS NULL AND sha256 = ?` 条件更新，保证幂等并避免覆盖并发修改；
4. 写入 UTC 时间戳到 `deleted_at`，提交后重新统计可处理组数；
5. 若没有安全组，直接返回，不创建备份、不写库。

## 发现与未处理

- 62 本“重复”中有 12 本是 410 错误页 / 0 字节文件；优先应**重新下载或标记源文件损坏**，而不是去重。相关书目与 P3-5 的 EPUB BadZipFile 探测失败、P3-6 的正文提取结果高度重合，可合并处理。

- 部分重复组的标题写法不同（同一本书不同下载命名），保留哪一本可能影响书架展示；`best` 只按封面/正文/标题质量排序，未做人工书目合并。
